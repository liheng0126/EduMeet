# E4 - 模型对比评测与选型基线

> 版本：v1.0 ｜ 状态：待评审 ｜ 上游：E0/E1 ｜ 联动：docs/spec/07 大模型接入与路由（P0/P1/P2 选型）

---

## 1. 目标与范围

主规划中模型不固定、按 P0/P1/P2 分批接入且可热切换。本 Spec 建立固定数据集上的「质量-成本-延迟」三维对比评测，为选型批次调整、降级链排序、默认模型切换提供量化依据。

## 2. 评测设计

### 2.1 统一条件（保证可比性）

| 条件 | 规格 |
|---|---|
| 数据集 | DS5 模型对比通用集 50 题（冻结版，永不改动） |
| 被评对象 | P0/P1/P2 全部在役模型 + 新候选（每模型 3 次全量运行取中位） |
| 评审 Judge | 与被评模型不同源（被评为国产模型时用 GPT-4o，反之用 GLM-5）；固定版本 |
| 调用通道 | 统一经 LiteLLM 网关，关闭降级（失败即记录），Langfuse trace 打 `model-eval` 标签 |
| Prompt | 各模型使用同一任务 Prompt（07 §7 模板），不做模型特定调优 |

### 2.2 三维度量

| 维度 | 度量 | 口径 |
|---|---|---|
| 质量分 | 加权综合分 | 政策事实准确×0.4 + 答案相关性×0.3 + 忠实度×0.2 + 结构完整×0.1（归一化 0~100） |
| 成本 | 元/标准任务 | 实测 token 用量 × 官网单价（与 Spec 11 积分公式同源）；生图按张 |
| 延迟 | 首Token P50/P95；任务总时长 P95 | 每 3 次运行取中位 |

## 3. 决策规则（选型复审输入）

```
升级为默认：质量分 ≥ 现役默认 × 95% 且 成本 < 现役 × 70%
进入降级链：质量分 ≥ 现役链内同档位 × 90% 且安全对抗集 100% 通过
移出降级链：连续两轮质量分在同档位垫底
一票否决：  DS4 安全对抗集未 100% 通过 → 不得接入任何批次
新批次准入：新模型上线前必须先过 DS4 + DS5 全量，报告归档模型台账
```

- 复审节奏：季度例会（E0 §6），产出《模型选型复审决议》：批次调整、降级链变更、模型台账更新（含官网价格核验）。
- 与 Spec 07 联动：决议直接更新 07 §2.1 预置模型表的批次/默认标记与 LiteLLM config。

## 4. 专项评测

| 专项 | 内容 | 频率 |
|---|---|---|
| 长文能力 | DS2 长文子集（>3000 字产出）对比 | 选型复审时 |
| 多模态识图 | Qwen-VL/GLM-4V/GPT-4o-mini 用 DS2 素材图 30 张打标准确率 | 选型复审时 |
| 生图质量 | 教育插画主题 20 prompt，Judge 盲评（隐藏模型名）1~5 分 + 版权合规检查 | 涉生图变更时 |
| 降级链演练 | 手动关停主模型，验证自动降级后的质量抽检 | 每次降级链变更 |

## 5. 产出物

1. 《模型对比矩阵报告》：三维散点/表格 + 同题对战样例（同一题各模型回答并排 + Judge 评语）。
2. 《选型复审决议》：批次变更 diff、LiteLLM config 变更 PR、模型台账更新。
3. 趋势曲线：同模型跨季度质量/成本变化（数据集冻结保证可比）。

## 6. 验收标准

- [ ] M2 交付首份 DS5 全量对比矩阵报告（覆盖 P0 全部 + P1 至少 2 个模型）
- [ ] Judge 与人评一致率 ≥ 85% 校准留档，且与被评模型隔离（盲测验证）
- [ ] 决策规则四条全部有真实演练记录（升级/进入/移出/一票否决各至少 1 例）
- [ ] 报告成本口径与 Spec 11 积分公式对平（误差 0）
- [ ] 一票否决规则演练：安全未过模型被阻止接入
