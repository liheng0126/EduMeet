# E6 - 计费正确性评测专项（资金级零容错）

> 版本：v1.0 ｜ 日期：2026-09-01 ｜ 状态：待评审
> 隶属：评测体系（评测/ 目录）；上游规则 Spec：docs/spec/11-账号会员与积分计费体系.md
> 定位：计费评测与内容质量评测有本质区别——不依赖 LLM 判断、全部为确定性断言、目标不是「尽量高」而是「必须零误差」。门禁与内容安全同级，一票否决。

---

## 1. 为什么是资金级

积分即真金白银（充值 1 元 = 10 积分，Spec 11）：

- **多扣**（误差 > 0）：直接客诉、退款补偿、平台信任损失；
- **少扣 / 逃逸**：付费模型被免费用户白嫖、利润系数失效，直接资损；
- **不幂等**：重试风暴重复扣费，事故级。

因此本专项的量化门禁全部为「= 0」型断言，不是比例型指标。

## 2. 评测范围与对象

| 对象 | 上游实现 | 说明 |
|---|---|---|
| 积分公式引擎 | Spec 11 §2（混合单价 3:1 加权 × 10 × 1.05，ceil 取整） | Billing Oracle 金标推导的唯一天然 |
| 扣费事务链路 | 两阶段扣费（预检冻结 → 按实际 usage 结算）、退款回冲 | Spec 11 §6 |
| 双余额 FIFO | 赠送（按月过期，先扣）+ 充值（永久，后扣） | Spec 11 §2/§7 |
| 沙箱控制 | LiteLLM 路由层强制校验 + 免费名单硬编码兜底 | Spec 11 §5、Spec 07 §4 |
| 错误码语义 | 40302 等级不足 / 40303 余额不足 / 40304 免费日额度用尽 | Spec 03 §12 |
| 对账链路 | 流水表 credit_ledger、余额快照、厂商账单 | Spec 11 §7 |

## 3. 评测方法：六类资金级用例（DS6，120 例）

### 3.1 公式 Oracle 测试（property-based）

```python
# 评测/evals/metrics/billing_oracle.py
# 金标与 Spec 11 公式同源；被测对象是主工程的计费实现
from hypothesis import given, strategies as st

@given(
    in_tok=st.integers(min_value=1, max_value=10**8),
    out_tok=st.integers(min_value=1, max_value=10**8),
    pricing=st.sampled_from(PRICE_TABLE),   # model_pricing 全档位
)
def test_credit_amount_matches_oracle(in_tok, out_tok, pricing):
    expected = oracle(pricing, in_tok, out_tok)   # ceil(混合价×10×1.05×实际百万token)
    actual = billing_engine.charge(pricing.model_ref, in_tok, out_tok, dry_run=True)
    assert actual == expected                    # 误差 = 0，无一例外
```

- 固定金标用例 40 例覆盖：ceil 取整边界（恰好整除 / 差 1 token 进位）、极端大/小 token、生图按张计价。
- 随机 fuzz 百万组合常驻 CI（billing 触发时全量跑，日常 Nightly 抽样 10 万组）。

### 3.2 扣费事务与幂等（20 例）

| 用例类 | 断言 |
|---|---|
| 同 ref_id 重放 N 次（N=1~50） | 仅扣 1 次，重复 = 0 |
| 结算阶段崩溃后补偿任务重跑 | 最终恰好结算 1 次，不多不少 |
| LLM 调用失败 / 部分成功 | 按实际 usage 结算；失败全额退还冻结额，退款误差 = 0 |
| balance_after 链 | 流水链条连续（前一条 after = 后一条 before），无跳变 |

### 3.3 双余额 FIFO（20 例）

- 赠送先扣、充值后扣的**序列断言**（逐笔核对扣减来源）；
- 月末过期边界：23:59:59 发起 / 00:00:01 结算的跨月用例，过期清零不误删充值余额；
- 加油包混扣、赠送 + 充值 + 加油包三源叠加；
- 余额永不为负（任何并发/失败组合下）。

### 3.4 并发竞态（20 例）

- 同账户 100 并发扣费 / 充值 / 退款混合压测：**恰好扣 N 次**（超扣 = 0、漏扣 = 0）；
- 事务隔离验证：行锁（SELECT FOR UPDATE）或乐观锁（version 字段）在竞态下正确性；
- 无死锁挂起（超时阈值内全部返回）；
- **隔离要求**：影子账户 + 独立 DB 实例，禁止污染生产数据；mock LLM 网关，零模型成本。

### 3.5 沙箱逃逸矩阵（20 例）

| 攻击向量 | 断言 |
|---|---|
| 免费用户 × 全部付费模型直连（S/A/B/C 全档） | 100% 自动降级 Free 并附 downgrade 提示 |
| 伪造 / 篡改 model_ref | 拒绝（未知模型不落默认放行） |
| 篡改响应 usage（中间人语义） | 服务端以网关返回为准重算，篡改无效 |
| SSE 流中断 | 按实际产生 usage 结算，不按预估多扣 |
| 免费日额度跨日重置边界 | 23:59:59 用尽 / 00:00:01 恢复，40304 语义正确 |
| 会员过期瞬间调用（过期边界竞态） | 按过期时刻等级判定，不出现「过期后仍用付费模型」窗口 |

### 3.6 对账三道闸（常驻 job，非一次性用例）

1. **请求内自检**：每笔扣费流水 balance_after 链连续性校验（实时）；
2. **T+1 日切对账**：日切时刻流水聚合 vs 余额快照核对，差异 = 0；差异 > 0 触发 P0 资损告警并冻结差异账户；
3. **月度厂商账单反核**：厂商账单实际 usage × 单价 vs 平台扣费流水，误差 = 0。

## 4. 故障注入（混沌用例，20 例）

| 注入点 | 期望 |
|---|---|
| 扣费服务宕机（结算阶段崩溃） | 恢复后补偿任务补齐，总额恰好正确 |
| 网络超时 + 重试风暴 | 幂等键防重，不重复扣 |
| LLM 网关部分失败 | 按实际 usage 结算 + 退还冻结额 |
| DB 主从延迟 | 余额读一致性，预检不穿透（不产生厂商成本） |
| 余额快照任务与扣费并发 | 快照一致性，日切对账仍平 |

## 5. 门禁与规则联动

- **发布门禁**：计费四项（公式误差 / 沙箱逃逸 / 幂等重复 / 对账差异）任一不为 0 → **禁止发布**，与安全一票否决同级；回滚到上一通过版本。
- **规则-用例版本绑定**：Spec 11 任何规则变更（单价 / 汇率 / 1.05 利润系数 / 等级权益）的 PR 必须同步更新 DS6 金标与断言；DS6 版本号与 Spec 11 版本号一致才允许跑发布门禁（评审 checklist 强制项）。
- **CI 触发**：`billing.yaml` 套件仅在计费相关代码 / 规则变更路径触发（git diff 路径匹配），避免拖慢常规迭代。
- **线上资损监控（联动 D8）**：扣费流水与网关 usage 小时级抽样比对、对账闸门定时任务、单笔异常大额（> P99.9）实时告警。
