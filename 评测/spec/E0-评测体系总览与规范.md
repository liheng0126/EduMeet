# E0 - EduMeet 评测体系总览与规范

> 版本：v1.0 ｜ 日期：2026-09-01 ｜ 状态：待评审
> 隶属：EduMeet 主项目（docs/spec/ 00~11）；本文件是评测体系入口，评测相关人员必读。

---

## 1. 目标

为 EduMeet 的智能体能力（文章生成、RAG 问答、检索、内容安全、计费）提供**可度量、可回归、可对比**的质量保障基建：

1. 每次模型切换 / Prompt 变更 / 链路上线都有量化数据支撑决策；
2. 教育政策类内容的事实准确性与内容安全达到零容忍级门禁；
3. 评测资产（数据集、Rubric、报告）版本化沉淀，随产品长期演进。

## 2. 评测对象与八大评测域

| 域 | 名称 | 评测对象 | 上游 Spec |
|---|---|---|---|
| D1 | 文章生成质量 | LangGraph 生成流水线产物 | docs/spec/04 |
| D2 | RAG 问答质量 | RAG 问答 Agent | docs/spec/04 |
| D3 | 检索质量 | 混合检索服务 | docs/spec/06 |
| D4 | 内容安全与未成年人保护 | 审核/核查 Agent + 全部 LLM 出口 | docs/spec/04/11 |
| D5 | Agent 行为可靠性 | Supervisor 状态机、工具调用 | docs/spec/04 |
| D6 | 模型横向对比 | P0/P1/P2 全部候选模型 | docs/spec/07 |
| D7 | 计费正确性（资金级） | 积分公式 / 扣费事务 / 沙箱 / 对账全链路 | docs/spec/11 |
| D8 | 线上效果反馈 | 生产流量埋点 | docs/spec/08/11 |

指标定义与门禁阈值见主规划 `评测/Agent评测体系建设规划.html`（v2.0）第 6 章总表；各域实现细节见 E2/E3/E4；计费资金级专项见 E6。

> **零容忍级指标（v2.0）**：政策实体准确率、时效标注率、对抗拦截率、不适宜图像、状态机异常、计费四项（误差/逃逸/幂等/对账）共 9 项为零容忍级——任一不达标禁止发布，一票否决。确定性指标（计费金额、拦截结果、结构完整性）一律走 L1/L2 确定性断言，禁用 LLM-Judge 评分。

## 3. 四层评测法

| 层 | 方法 | 适用 | 成本 |
|---|---|---|---|
| L1 | 规则校验 | 结构/格式/引用可访问/时效标注存在性/计费金额确定性断言 | 零 |
| L2 | 统计指标 | NDCG、MRR、Recall、RAGAS 四件套；property-based 随机组合 fuzz（计费公式扫描） | 低 |
| L3 | LLM-as-Judge | 事实准确、要点覆盖、图文相关、教育适配 | 中 |
| L4 | 人工评审 | 金标校准、仲裁、发布抽检 20% | 高（仅关键场景） |

**Judge 可信度红线**：Judge 模型与被评模型不同源；上岗前对 50 条人工标注盲测一致率 ≥ 85%；Rubric 存 Git 版本化；评分隐藏模型来源、打乱顺序。

## 4. 工程与仓库约定

```
评测/
├── Agent评测体系建设规划.html      # 本体系规划
├── spec/                           # E0~E6 本文档体系
└── evals/                          # 评测工程（E5 定义，随 M1 起步建设）
    ├── datasets/                   # DS1~DS6 JSONL + VERSIONS.md（DS6 与 Spec 11 版本号绑定）
    ├── metrics/                    # l1_rules / l2_stats / l3_judge / billing_oracle
    ├── suites/                     # smoke / nightly / release / billing(资金级) 套件 YAML
    ├── runner.py                   # 执行器
    └── reports/                    # HTML 报告 + JSON 指标产物
```

- 数据集与 Rubric 变更走 Git PR 评审；版本冻结（如 `ds1-v1.0`）后才可用于门禁。
- 评测调用一律经主工程 LiteLLM 网关，保证 trace 进入 Langfuse（复用 `评测` 标签隔离流量）。
- 报告产物按运行 ID 归档 `reports/{run_id}/`，趋势数据写看板存储。

## 5. 角色与职责

| 角色 | 职责 |
|---|---|
| 评测负责人 | 数据集治理、指标口径、报告评审、选型复审组织 |
| AI 后端 | 被测链路的可测性改造（trace/可注入故障）、失败归因 |
| 业务标注 | DS1~DS4 标注（双人+仲裁），家长/教师视角审核 |
| DevOps | CI/Nightly 流水线、门禁集成、看板运维 |
| 测试开发 | E6 计费资金级专项：Billing Oracle、并发/混沌用例、对账三道闸 |

## 6. 运行节奏

| 节奏 | 内容 |
|---|---|
| 每 PR | Smoke 套件（≤10 分钟）门禁 |
| 每夜 | 全量评测 + 劣化告警（>3%） |
| 每发布 | 全量门禁 + 人工抽检 20%；计费四项零容忍级断言全绿 |
| 每日（T+1） | 计费日切对账闸门（E6 §3.6） |
| 每月 | 厂商账单反核（实际 usage × 单价 vs 扣费流水，误差 = 0） |
| 每季度 | 模型选型复审（E4）、标注漂移审计、评测集扩容 +20% 难例、Judge 复测 |

## 7. 验收标准

- [ ] 本文档体系（E0~E6）评审通过并纳入主项目 00-总览索引
- [ ] DS6 资金级用例集与 Billing Oracle 随 M3 会员计费上线同期交付，计费四项断言全绿
- [ ] 评测/evals 骨架随 M1 建立，smoke 套件接入 CI
- [ ] 全部指标口径在本文档与 E2/E3 中有唯一定义，报告可复现（相同 run 环境重跑误差 0）
