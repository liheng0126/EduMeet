02平台建设背景

2.1 要解决的问题

中小学教育信息在家长侧长期存在三类痛点，EduMeet 以「AI Agent + 内容平台」双形态针对性解决：

📉

入学政策信息不对称

升学政策分省市、分学段、逐年变化，散落在教育部门网站与自媒体，家长检索成本高且极易被过时信息误导。

🧩

经验分散难获取

学习经验、家庭教育思路、教师教学经验分散在社交平台，质量参差、缺少面向教育场景的结构化沉淀与分发。

⏱

资料整理费时费力

学习资料收集与整理高度依赖人工，缺少「导入素材 → AI 融合生成 → 沉淀复用」的一体化工具。

2.2 平台定位与核心能力

面向家长 / 学生 / 教师三类角色的网页版教育 Agent 平台，主题聚焦：全国中小学生入学政策、学习资料、家庭教育思路分享、学生学习经验分享、教师教育经验分享。核心能力包括：对标 ChatGPT 的三栏会话式布局；文章 AI 自动生成并自动绑定作者账号（图文模式，5-Agent 流水线）；文章检索与图文阅读器（混合检索 + 块级文档展示）；自定义素材导入（文章/图片/视频）并融合进文档；用户自选大模型（LiteLLM 统一路由）；内容来源 = 开源网络文章（白名单采集）+ 平台私有文章（原创沉淀）。

2.3 建设路线

按 M1~M5 五个里程碑推进：M1 基础框架与生成链路冒烟 → M2 检索/图文/评测平台完整落地 → M3 会员积分计费（资金级评测同期全绿）→ M4 运营增强与线上反馈 → M5 桌面版 SDK（Tauri + 开放 SDK，终期）。工作模式：先文档评审、后代码，每份 Spec 附验收标准。

03平台建设难点与对应解法

🎯

难点 1：教育政策内容零容忍出错

面向家长的升学决策建议一旦幻觉出错，后果严重且不可逆。
解法：政策回答强制引用官方来源 + 核查 Agent 事实核验（召回 ≥95%）+ 时效标注 100% + 用户纠错入口；评测门禁实体级准确率 ≥98%，一票否决。

🔄

难点 2：模型不固定、成本敏感

大模型随行情热切换，图文质量与成本差异大。
解法：LiteLLM 统一路由，P0/P1/P2 分批接入高性价比图文友好模型；DS5 固定集季度跑分「质量-成本-延迟」三维矩阵驱动选型；沙箱控制免费用户仅用免费模型。

🧩

难点 3：多智能体链路复杂

文章生成是 规划→写作→配图→核查→审核 5-Agent 流水线，任一 Prompt 变更都可能级联退化。
解法：逐环节量化记分卡（17 项指标）+ Nightly 回归 + 劣化归因矩阵，定位到环节而非只知变差。

💰

难点 4：计费是资金级零容错

积分扣费（1 元 = 10 积分，5% 利润系数，双余额 FIFO）多扣伤信任、少扣是资损。
解法：Billing Oracle 百万组合 fuzz + 幂等/并发/沙箱逃逸矩阵 + 对账三道闸，四项断言「误差 = 0」方可发布。

🛡

难点 5：未成年人内容安全与合规

面向未成年人的内容安全红线高于一般平台，且上线需备案资质。
解法：审核 Agent 对抗拦截 100%（一票否决）+ 误杀率 ≤5% 平衡可用性；ICP/算法/生成式 AI 备案 M1 并行启动；AI 内容标识与青少年模式。

🌱

难点 6：内容冷启动与版权

平台初期无内容、无用户，检索质量无从谈起；开源采集有版权风险。
解法：官方预置分省市政策库与精选经验种子池 + 创作者积分激励；白名单采集 + 来源标注 + 版权申诉通道。

04评测体系汇总

定位：评测体系是 EduMeet 的质量基础设施，与业务同步建设——冒烟评测随 M1 交付、评测平台随 M2 落地、计费资金级专项随 M3 与会员计费同期全绿、模型对比每季度驱动选型复审。

4.1 八大评测域

域评测对象核心量化门禁
D1 文章生成质量5-Agent 流水线产物（逐环节）政策实体准确率 ≥98%、要点覆盖 ≥80%、图文相关 ≥4.0
D2 RAG 问答质量RAG 问答 Agent忠实度（RAGAS）≥0.90、时效标注率 100%
D3 检索质量混合检索服务NDCG@10 ≥0.75、时效版本正确率 ≥95%
D4 内容安全审核/核查 Agent + 全部 LLM 出口对抗拦截率 100%（一票否决）、误杀率 ≤5%
D5 Agent 行为Supervisor 状态机 / 工具调用任务完成率 ≥90%、状态机异常 = 0
D6 模型对比P0/P1/P2 全部候选模型质量-成本-延迟矩阵，报告驱动选型
D7 计费正确性（资金级）积分公式/扣费事务/沙箱/对账误差、逃逸、幂等重复、对账差异 全部 = 0
D8 线上效果反馈生产流量埋点趋势监控 + 资损告警即时响应

4.2 方法与数据集

四层评测法：L1 规则断言（含计费确定性断言）→ L2 统计指标（NDCG/RAGAS/property-based fuzz）→ L3 LLM-as-Judge（与人评一致率 ≥85% 方可上岗，确定性指标禁用 Judge）→ L4 人工评审（发布抽检 20%）。六大数据集：DS1 政策金标 200 题（含时效陷阱）、DS2 生成种子集、DS3 检索评测集、DS4 安全对抗集（PyRIT 季度扩容）、DS5 模型对比通用集、DS6 计费资金级用例 120 例（与 Spec 11 版本号绑定），全部 Git 版本化。

4.3 零容忍级指标（9 项，任一不达标禁止发布）

政策实体准确率 ≥98% ｜ 时效标注率 100% ｜ 对抗拦截率 100% ｜ 不适宜图像 = 0 ｜ 状态机异常 = 0 ｜ 计费金额误差 = 0 ｜ 沙箱逃逸 = 0 ｜ 幂等重复扣费 = 0 ｜ 对账差异 = 0。

4.4 计费资金级专项（评测体系的最重保障）

四项「= 0」断言一票否决：①Billing Oracle 以 Spec 11 公式为天然做 property-based 百万组合 fuzz；②同 ref_id 重放 N 次仅扣 1 次（幂等）；③同账户 100 并发恰好扣 N、无负余额（竞态）；④对账三道闸（请求内自检 / T+1 日切 / 月度厂商账单反核）差异 = 0。计费规则变更的 PR 必须同步更新 DS6，规则与用例版本绑定，防漂移。

4.5 上线门禁节奏

PR 合入跑 Smoke 套件（≤10 分钟，涉计费代码加跑 DS6 组合矩阵）→ Nightly 全量回归 + 逐环节记分卡与劣化归因 → 版本发布全量六数据集 + 9 项零容忍级断言全绿 + 人工抽检 20% → 报告产出机读 verdict: PASS/BLOCKED，BLOCKED 拦截发布并附回滚指引。
