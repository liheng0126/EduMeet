## 1. 项目背景

EduMeet 是面向全国中小学生教育场景的网页版 AI 智能体平台，围绕「入学政策 / 学习资料 / 家庭教育思路 / 学生学习经验 / 教师教育经验」五大主题，为家长、学生、教师提供信息聚合、AI 图文生成与经验分享服务。

**核心问题**：家长在入学政策、教育方法上存在严重信息偏差；优质教育经验分散且难以沉淀检索。

**核心方案**：开源内容聚合（公共内容库）+ 账号私有内容（AI 生成 + 用户创作）+ 混合检索 + 对话式问答。

## 2. 术语表

| 术语 | 定义 |
|---|---|
| 会话（Session） | 一次多轮对话上下文，含消息列表与引用 |
| 文章（Article） | 平台最小内容单元，块级 JSON 文档模型，支持图文/视频混排 |
| 素材（Material） | 用户导入的文章/图片/视频/文档/URL，可被文章与生成流程引用 |
| 块（Block） | 文档内容的最小结构单元（段落/标题/图片/视频/引用等） |
| 生成任务（GenTask） | 一次文章自动生成的异步任务，含多 Agent 阶段状态 |
| 公共内容库 | 来源于开源网络文章、经治理后的公开内容集合 |
| 私有文章 | 归属具体账号的文章，权限为 私有/可见/公开 |
| 模型路由 | 按「用户选择的模型标识」将 LLM 请求转发到对应供应商 |

## 4. 技术栈约定

| 层 | 技术 |
|---|---|
| 前端 | Vue3（Composition API）+ TypeScript + Vite + Element Plus + Pinia + Vue Router + TipTap |
| 后端 | Python 3.11+ + FastAPI + SQLAlchemy 2.0（async）+ Pydantic v2 |
| AI 编排 | LangGraph（Supervisor 模式）+ LiteLLM |
| 存储 | PostgreSQL 16（+ pgvector）、Redis 7、Elasticsearch 8（IK 分词）、S3 兼容 OSS |
| 任务 | Celery + Redis Broker；Celery Beat 定时 |
| 部署 | Docker Compose（一期），预留 K8s |
| 可观测 | Langfuse（LLM 追踪）、结构化日志、Prometheus 指标 |
| 桌面端（终期 M5） | Tauri 2.x + Rust + 系统 WebView + tauri-plugin 插件矩阵；打包签名/自动更新方案见 Spec 12 |
| 开放 SDK（终期 M5） | TypeScript 5 + tsup + zod + changesets（npm）；Python httpx + pydantic v2 + uv（PyPI）；契约 CI 对齐 Spec 03 |

### 5.2 编码约定

- 后端：`ruff` + `mypy`；接口统一响应包 `{code, message, data}`；异常统一错误码（见 03 文档附录）。
- 前端：`eslint` + `prettier`；组件用 `<script setup lang="ts">`；API 调用必须走 `src/api` 封装，禁止组件内直连 axios。
- Git：main / develop / feature 分支模型；提交信息 `feat|fix|docs|refactor(scope): xxx`。
- 数据库：所有变更走 Alembic 迁移，禁止手工改库。

### 5.3 联调约定

- 接口契约以 `03-API接口设计.md` + OpenAPI（FastAPI 自动生成 `/docs`）为准，前端可先按契约 Mock。
- SSE 流式接口统一事件格式：`event: {message_delta | task_progress | error}`，`data: JSON`。
- 环境分 dev / staging / prod；配置走环境变量 + `.env`，密钥不入库入 Git。

## 6. 全局红线（各模块 Spec 均须遵守）

1. **内容安全**：AI 生成与 UGC 发布必须过安全审核节点，涉未成年人隐私内容一律拦截。
2. **政策准确性**：政策类回答/文章必须带来源引用与时效提示。
3. **版权**：开源文章入库必须记录来源 URL 与许可；用户素材须声明所有权。
4. **账号绑定**：所有生成/创作内容落库时必须写入 `author_id`，不允许存在无主内容。
5. **隐私**：不采集未成年人身份信息；用户 API Key 加密存储。

## 7. 验收基线

- 单元测试覆盖率：后端核心 service ≥ 70%，AI 编排链路必须有集成测试。
- 接口 100% 符合 03 文档契约；SSE 事件名与数据结构不得私自变更。
- 每个模块交付时附自测清单，对照所在 Spec 文档的「验收标准」章节逐项确认。
